# 矿井瓦斯班测台

检查员上报测点甲烷浓度。达到 1% 时，服务端通过网页套接字把这条报警推到已经打开的页面。页面是手写脚本，没有用组件框架，也没有图表。

新上报强制填写**风速、巷温、仪器编号**三栏，缺一不可；缺栏时服务端返回 400，既不入库也不推送。三栏在数据库中各自独立存字段。每次成功上报会把三栏原文写入该行的三栏履历；事后改正某一栏时只追加新快照，旧履历行保持改正前原文。总表支持按仪器编号片段由服务端过滤，过滤条件可存成命名方案供下次一键套用。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3191 |
| 接口 | http://localhost:8191 |
| PostgreSQL | localhost:54391 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| gasman | gas123456 | 上报、改正、过滤、看履历、新建过滤方案 |
| viewer | view123456 | 过滤、看履历、套用方案；不能上报、改正或新建方案 |

## 启动

```bash
docker compose up --build
```

旧库启动时会自动给 `readings` 表补齐三列（`wind_speed`、`roadway_temp`、`instrument_no`，可空），旧行照常显示，三栏以“—”呈现。

## 主要接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/readings` | 上报，三栏缺失返回 400，不入库不推送 |
| GET | `/api/readings?instrument=片段` | 服务端按仪器编号片段（ILIKE）过滤 |
| PATCH | `/api/readings/{id}` | 改正三栏（须三栏齐全），追加履历快照 |
| GET | `/api/readings/{id}/histories` | 查看三栏履历（两个角色均可） |
| GET/POST | `/api/filter-schemes` | 命名过滤方案；POST 仅检查员 |

## 验收

1. 用 gasman 登录，列表里回风巷是报警，东翼-12 是正常，两条旧种子行三栏显示“—”。
2. 上报时不填风速，页面停住提示缺栏；接口返回 400，列表无新行，其他打开的页面也收不到推送。
3. 补齐风速后上报成功，两个窗口都会出现新记录，新行带三栏原文。
4. 在过滤框输入仪器编号片段（如 `8864`），列表只剩该仪器的新行；把该片段存为命名方案后，下次从下拉一键选择即恢复同样过滤。
5. 展开该行履历可看到上报时的巷温原文；点“改正”把巷温改成新值保存后，履历新增一条“改正”记录，旧的“上报”记录里巷温仍是改正前原文。
6. viewer 登录后没有上报表单和改正按钮，可以过滤、看履历、套用方案，但直接调接口上报、改正或新建方案均返回 403。
