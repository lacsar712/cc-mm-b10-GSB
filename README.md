# 矿井瓦斯班测台

检查员上报测点甲烷浓度。达到 1% 时，服务端通过网页套接字把这条报警推到已经打开的页面。页面是手写脚本，没有用组件框架，也没有图表。

上报时**风速、巷温、仪器编号三栏强制填写，缺一不可**；缺栏时既不入库也不推送。三栏原文各自独立存字段，每次成功上报都会把三栏原文写入三栏履历；事后改正某一栏时，旧履历行保留改正前的原文。总表支持按仪器编号片段由服务端过滤，过滤条件可存成命名方案，下次一键套用。旧种子数据没有三栏仍照常显示（显示为 —），新上报的行三栏必须齐全。

## 启动

```bash
cd projects/12-mine-methane-shift
docker compose up --build
```

旧版本数据库启动时会自动给 `readings` 表补上三栏，旧行保持空值；履历表和方案表自动创建。

## 验收

1. 用 gasman 登录，列表里回风巷是报警，东翼-12 是正常，两条旧行的三栏显示 —。
2. 上报时不填风速，上报被停住（前端提示、服务端 422），列表不新增、其他页面收不到推送。
3. 补齐风速等三栏后再报，新行出现并推送到所有已打开页面，风速/巷温/仪器编号各为所填原文。
4. 在过滤框填仪器编号片段（如 `JFY`），只看到仪器编号含该片段的新行，旧行被服务端过滤掉。
5. 把该片段存为命名方案；刷新页面后在下拉中一键套用，过滤效果一致。viewer 登录看不到保存方案的输入。
6. 点该新行的「履历」，看到三栏首次录入原文；把巷温改成新值后，履历新增一行（旧值→新值），上一行仍显示改正前的巷温。
7. viewer 登录可过滤、可点「履历」查看，但没有上报表单和改正表单，直接调上报/改正/建方案接口返回 403。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/readings?instrument=片段` | 登录 | 服务端按仪器编号片段过滤 |
| POST | `/api/readings` | writer | 三栏必填，缺栏 422；成功同事务写三栏履历并推送 |
| PATCH | `/api/readings/{id}` | writer | 只提交要改正的栏，追加履历、旧行不动 |
| GET | `/api/readings/{id}/history` | 登录 | 查看三栏履历原文 |
| GET/POST | `/api/filter-schemes` | 登录 / writer | 列出方案（viewer 可套用）/ 新建方案（仅 writer） |
